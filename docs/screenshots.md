# Lockverity v1.2 — Screenshot Checklist

This is the reviewer-friendly screenshot checklist for the v1.2
local demo. The screenshots are **not** stored in this
repository; capture them in a separate portfolio folder
alongside your review notes. The checklist below is the
contract a portfolio review should be able to verify against.

Every screenshot must surface the v1.2 demo-dataset notice
("Demo evidence: synthetic persisted dataset generated by
Lockverity's demo loader.") so the reviewer can never mistake
the demo data for real provider scan results.

## Capture order

Capture the screenshots in the order below. The order matches
the demo flow in [`docs/demo-walkthrough.md`](demo-walkthrough.md)
and the `Run the demo` section of [`README.md`](../README.md).

### 1. Scan list (4 scans, all four terminal states)

- **URL**: `http://127.0.0.1:5173/`
- **Expected visible state**:
  - The page header reads `Scans`.
  - Four rows: scan 1 (completed), scan 2 (partial),
    scan 3 (failed), scan 4 (cancelled).
  - The status badges are colour-coded: emerald for
    completed, amber for partial, rose for failed, ink-100
    for cancelled. The badges never claim "clean" for failed
    or cancelled.
  - The demo-dataset notice is visible above the table.

### 2. Dependency Explorer — default state

- **URL**: `http://127.0.0.1:5173/scans/1/dependencies`
- **Expected visible state**:
  - The page header reads `Dependencies · scan #1`.
  - The evidence filters card is visible with all 9 filter
    fields and a `Clear` button (hidden by default).
  - The facets panel shows 13 aggregate counts:
    ecosystems, missing version, missing licence evidence,
    missing provider evidence, PURL persisted /
    constructible / omitted, edges observed / none observed,
    direct yes / no, CycloneDX 1.7 version omitted.
  - The component table has 6 rows:
    `alpha`, `beta`, `gamma`, `left-pad`, `right-pad`, `stay`.
  - The demo-dataset notice is visible above the table.

### 3. Dependency Explorer — search filter

- **URL**: `http://127.0.0.1:5173/scans/1/dependencies`
- **Expected visible state** (after typing `left` in the
  search box):
  - The table narrows to a single row (`left-pad`).
  - The `Clear` button appears in the card header.
  - The facet counts update to reflect the filtered set.

### 4. Component evidence drawer

- **URL**: `http://127.0.0.1:5173/scans/1/dependencies`
- **Expected visible state** (after clicking `View evidence`
  on the `left-pad` row):
  - The right-side drawer opens.
  - The drawer shows the read-only v0.8 evidence panel with
    6 sections: identity, manifest evidence, licence
    evidence, provider evidence, dependency evidence, export
    implications.
  - An "evidence-honesty markers" list is at the bottom.

### 5. CycloneDX 1.7 evidence preview

- **URL**: `http://127.0.0.1:5173/scans/1/exports`
- **Expected visible state** (after clicking `Show CycloneDX
  1.7 evidence preview`):
  - The preview panel expands with the eligibility verdict
    (`eligible` for the demo dataset) and the SBOM output

    template, schema URI, validation, generation source).
  - The omissions block is visible.
  - The legacy-export-relationship note is visible.

### 6. Downloaded CycloneDX 1.7 SBOM

- **File**: `lockverity-scan-1.cdx.json` (the file your
  browser saved when you clicked `Download` on the CycloneDX
  1.7 row).
- **Expected visible state** (open in a JSON viewer):
  - The file validates against the official
    `JsonStrictValidator(SchemaVersion.V1_7)`.
  - The `metadata.tools` block lists Lockverity and the
    `lockverity` analyzer version.
  - The `components` array contains 6 entries.
  - The `dependencies` array contains 2 entries.
  - The serial number is deterministic for the same
    persisted evidence.

### 7. Evidence report preview

- **URL**: `http://127.0.0.1:5173/scans/1/exports`
- **Expected visible state** (after clicking `Show report
  summary` on the Evidence report card):
  - The bounded disclaimer block is visible at the top:
    "This is an evidence report, not a security verdict,
    not a certification, and not a compliance pass-or-fail."
  - The preview shows the seven documented sections:
    metadata, scan identity, scan summary, evidence
    coverage, evidence gaps, component table, export
    relationship.
  - The omissions list is visible.

### 8. Downloaded Markdown evidence report

- **File**: `lockverity-scan-1.evidence-report.md` (the file
  your browser saved when you clicked `Download Markdown`).
- **Expected visible state** (open in a Markdown viewer):
  - The file contains a GitHub-flavoured Markdown report
    with all 7 sections.
  - The bounded disclaimer is a quote block at the top.
  - The component table is capped at 100 rows; the demo
    dataset fits in 6 rows.
  - The Markdown is byte-stable: opening the file twice
    and `diff`-ing them produces no output.

### 9. Failed / cancelled scan — bounded empty state

- **URL**: `http://127.0.0.1:5173/scans/3/exports` (failed)
  or `http://127.0.0.1:5173/scans/4/exports` (cancelled)
- **Expected visible state**:
  - The Evidence report card renders a preview with 0
    components, 0 manifests, and `not_applicable` coverage
    on all three dimensions.
  - The CycloneDX 1.7 export eligibility verdict is
    `no`.
  - The Markdown body contains the bounded "no components
    recorded" message.
  - The UI does **not** fabricate a clean verdict for a
    failed or cancelled scan.

### 10. About page

- **URL**: `http://127.0.0.1:5173/about`
- **Expected visible state**:
  - The page header reads `About` and shows the v1.2
    version.
  - The v1.0 human-readable evidence report bullet is
    visible.
  - The bounded `What v1.2 does not include` section is
    visible.
  - The provider-honesty and non-execution guarantees are
    repeated verbatim from the source code.

## What not to claim in a review

Do **not** write any of the following in a review document
or in screenshot captions:

- "The SBOM is a certified bill of materials." The CycloneDX
  1.7 export is evidence, not a certification. The schema
  validates, but the export is not signed and does not
  carry a trust assertion.
- "The dependency graph is complete." The v0.6 helper
  returns `partial` for the demo dataset.
- "No findings" because a provider was unavailable, rate-
  limited, or skipped. The demo's three provider
  observations are explicit `AVAILABLE` or `RATE_LIMITED`
  rows, never silent omissions.
- "The demo dataset is a real provider scan result." The
  fixture repository is `https://github.com/example-org/lockverity-fixture`,
  the resolved commit SHA is the `deadbeef` fill, and
  Lockverity makes no provider calls during the demo.

## Capture checklist (reviewer-facing)

Use this checklist when you review the captured screenshots:

- [ ] Scan list shows four scans with honest status badges.
- [ ] Dependency Explorer default state shows 6 components.
- [ ] Dependency Explorer search narrows to 1 row (`left-pad`).
- [ ] Component evidence drawer has 6 sections and the
  omissions list.
- [ ] CycloneDX 1.7 evidence preview shows the eligibility
  verdict and the SBOM output facts.
- [ ] Downloaded CycloneDX 1.7 SBOM validates against the
  official `JsonStrictValidator(SchemaVersion.V1_7)`.
- [ ] Evidence report preview shows the bounded disclaimer
  and the seven sections.
- [ ] Downloaded Markdown evidence report is byte-stable
  (open twice, `diff`, no output).
- [ ] Failed / cancelled scan report shows the bounded
  `not_applicable` empty state and the "no components
  recorded" wording.
- [ ] About page lists the v1.2 milestone and the bounded
  "What v1.2 does not include" section.
- [ ] Every page surfaces the demo-dataset notice where
  implemented.
- [ ] No screenshot caption over-claims the SBOM, the
  report, or the dependency graph.
