# Lockverity v2.0.6 — Screenshot Checklist + Manual Capture Guide

This is the reviewer-friendly screenshot checklist for the v2.0.6
local demo. The screenshots are **not** stored in this
repository; capture them in a separate portfolio folder
alongside your review notes. The checklist below is the
contract a portfolio review should be able to verify against.

Every screenshot must surface the v2.0.6 demo-dataset notice
("Demo evidence: synthetic persisted dataset generated by
Lockverity's demo loader.") so the reviewer can never mistake
the demo data for real provider scan results.

## Status of the screenshot assets

The v2.0.6 release does **not** ship image files. The
application code never has a headless-browser dependency and
none is added in v2.0.6. The 9 reviewer captures below are
**manual**: a reviewer runs the demo on their own laptop and
uses their own browser's screenshot tool. This is intentional
because:

- The portfolio reviewer already needs the demo running
  locally to verify the v0.5–v1.2 surfaces interactively.
  A captured set of screenshots would duplicate the evidence
  they can produce in five minutes.
- Auto-captured screenshots would have to ship browser
  binaries (Playwright, headless Chrome, or a similar
  dependency) and would also bake-in the current UI styling
  to a frozen point in time. Lockverity's UI is read-only and
  is expected to evolve with the application; the live demo
  is the canonical evidence.
- Lockverity's boundaries are explicit: no analysed
  repository code is ever executed, no provider credentials
  are ever stored, and the demo dataset is synthetic
  persisted evidence. Auto-captured screenshots make it
  harder to verify these boundaries because the reviewer
  would have to trust that the image they see was actually
  produced by the running application.

The manual capture instructions below are designed to be
fast (about 10 minutes total), reproducible, and free of any
new tooling.

### 7. Downloaded Markdown evidence report

- **File**: `lockverity-scan-1.evidence-report.md` (the file
  your browser saved when you clicked `Download Markdown`).
- **Expected visible state** (open in a Markdown viewer,
  e.g. a text editor or a GitHub-rendered preview):
  - The file contains a GitHub-flavoured Markdown report
    with all 7 sections.
  - The bounded disclaimer is a quote block at the top.
  - The component table is capped at 100 rows; the demo
    dataset fits in 6 rows.
  - The Markdown is byte-stable: opening the file twice
    and `diff`-ing them produces no output.

    `diff` two downloads to confirm that the same

### 8. Failed / cancelled scan — bounded empty state

- **URL**: `http://127.0.0.1:5173/scans/3/exports` (failed)
  or `http://127.0.0.1:5173/scans/4/exports` (cancelled)
- **Expected visible state**:
  - The Evidence report card renders a preview with 0
    components, 0 manifests, and `not_applicable` coverage
    on all three dimensions.
  - The CycloneDX 1.7 export eligibility verdict is
    `no`.
  - The Markdown body contains the bounded "no components

  - The UI does **not** fabricate a clean verdict for a
    failed or cancelled scan.
- **Why it matters**: the bounded empty state is the
    single most important reviewer signal that Lockverity
    is honest. A "no findings" verdict on a failed or
    cancelled scan would be the v0.4 evidence-honesty
    violation we explicitly do not allow.

- **URL**: `http://127.0.0.1:5173/about`

  - The bounded `What v2.0.6 does not include` section is

  - The provider-honesty and non-execution guarantees are

- **Why it matters**: the About page is the single source
    of truth for the current milestone and the product
    boundaries. The `What v2.0.6 does not include`
    section is the explicit list of what Lockverity does
    not claim.

## Manual capture instructions (browser-agnostic)

The 9 captures are designed to be taken in about 10 minutes
on a single browser. The instructions below are written
against the keyboard shortcuts that work in every modern
browser; if a browser's shortcut differs, use the equivalent
menu path.

### Pre-capture checklist

1. **Close unrelated tabs.** Only the Lockverity demo tab
   should be open. Browser tabs may show personal
   identifiers (account avatars, mail counts, etc.) that
   the screenshot should not capture.
2. **Disable browser extensions** that draw over the page
   (password managers, ad blockers, dark-mode forced
   overrides, translation banners, etc.). The screenshots
   must show the application's own styling, not a browser
   extension's overlay.
3. **Use a private / incognito window** if the browser
   profile carries signed-in state to GitHub, a password
   manager, or any other service. The demo itself does not
   call any provider, but the browser chrome should not
   show personal state either.
4. **Set the browser window** to a 1280x800 or 1440x900
   viewport. The Tailwind layout is responsive but the
   screenshots are most reviewable at desktop sizes.
5. **Start the demo** (`./scripts/load_demo.py` + uvicorn +
   `npm run dev`) and verify the backend reports version
   `1.3.0` at `http://127.0.0.1:8765/api/v1/health`.

### Per-capture shortcuts

- **macOS**: `Cmd+Shift+4` then `Space` (capture window) or
  drag to capture a region. `Cmd+Shift+5` opens the capture
  menu.
- **Windows**: `Win+Shift+S` opens the snipping tool.
  `PrtSc` captures the full screen; `Alt+PrtSc` captures
  the active window.
- **Linux**: `PrtSc` (full screen), `Shift+PrtSc` (region).
  GNOME has a screenshot tool in the Activities overview;
  KDE has `Spectacle`.

The captures should be saved as PNG (lossless) into a
portfolio folder such as `~/lockverity-portfolio/v2.0.6/`.
The 9 filenames above sort alphabetically into the
intended review order.

### Post-capture checklist (sensitive data)

After each capture, look at the saved file and verify it
contains **none** of the following:

- Personal browser profile info: account avatar, mail
  count, browser tab title from another tab, password
  manager dropdown.
- GitHub tokens, OAuth banners, signed-in indicator
  showing your username, or any "this token has access
  to..." overlay.
- Local filesystem paths from another application (a
  terminal window, a file manager, a code editor's
  breadcrumbs pointing at the developer's local home
  directory).
- Personal information: your real name, email, phone, home
  directory, employer.
- Unrelated tabs / bookmarks / search-engine suggestion
  dropdowns / extension popups.

If any of the above appears, recapture the screenshot
without the offending element. The most common culprit is
the operating-system notification bar (Windows toast
notifications, macOS notifications) — close those before
each capture.

The demo application itself does not render any of the
above; the application has no avatar component, no
filesystem breadcrumb, no GitHub-login widget, and no
suggestion dropdown. The post-capture checklist exists
because the *browser chrome around the application* can
leak personal data, not because the application does.

## What not to claim in a review

Do **not** write any of the following in a review document
or in screenshot captions:

- "The SBOM is a certified bill of materials." The CycloneDX
  1.7 export is evidence, not a certification. The schema
  validates, but the export is not signed and does not
  carry a trust assertion.
- "The dependency graph is complete." The v0.6 helper
  returns `partial` for the demo dataset.
- "No findings" because a provider was unavailable, rate-
  limited, or skipped. The demo's three provider
  observations are explicit `AVAILABLE` or `RATE_LIMITED`
  rows, never silent omissions.
- "The demo dataset is a real provider scan result." The
  fixture repository is `https://github.com/example-org/lockverity-fixture`,
  the resolved commit SHA is the `deadbeef` fill, and
  Lockverity makes no provider calls during the demo.

      verdict and the SBOM output facts.
- [ ] Evidence report preview shows the bounded disclaimer
      and the seven sections.
- [ ] Downloaded Markdown evidence report is byte-stable
      (open twice, `diff`, no output).
- [ ] Failed / cancelled scan report shows the bounded
      `not_applicable` empty state and the "no components

      "What v2.0.6 does not include" section.

      report, or the dependency graph.

      GitHub tokens, real filesystem paths, or unrelated
